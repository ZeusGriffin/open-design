# LEAN BUILD
## Goal and context
Deliver reliable, maintainable functionality with minimum necessary code, dependencies, tokens and execution time. Complement Karpathy, Token Saver, Caveman, Baseline Lock and Verification Gate; do not duplicate their duties.
## Rules
1. Inspect project state and reuse verified components.
2. Compare native capabilities, lightweight libraries and established frameworks when architecture decisions are needed.
3. Justify dependencies; never reinvent mature libraries without measurable advantage.
4. Read only relevant files; use compact state summaries and targeted patches.
5. Preserve working behavior and design; avoid unnecessary abstractions.
6. Run targeted tests before broad tests; do not repeat failed approaches without new evidence.
7. Record reusable findings, blockers and smallest next action.
8. Report changes, dependencies, test results and measured token usage if available; never invent savings or hardware verification.
## Trigger
Default for all development work; skip unnecessary architecture review for simple edits. Existing verification and safety requirements take precedence.
